# The number of mutation entries that must exist in checks/mutations.ts.
#
# Same job as checks/test_count_floor.txt, one layer out. That file stops the
# SUITE losing tests silently. This one stops the HARNESS losing the entries
# that prove the suite can fail, which is the thing that decides whether the
# suite is worth anything.
#
# Why it exists: the count was got wrong in both directions. A build reported 38
# entries and a cold verification pass reported 37, each stated twice, and
# neither had a command beside it. check.ts prints only "pass (103.4s)" for the
# mutation step and discards the harness's own count line, so nobody running
# `bun run verify` ever saw the real number. Both parties fell back to counting
# an array by eye.
#
# 38 was correct. It is now 60. Twelve were added for the four defects the
# first cold verification pass found in the shipped artifact (D1 to D4), taking
# it to 50. Ten more were added for the three the SECOND cold pass found: F1
# (the size cap dropped rows uncounted and cut the last one mid-value), F2 (six
# count assertions that were satisfied incidentally by the fixture rather than
# by the notice they named) and F5 (the host declared as a hard dependency).
#
# 60 to 65 by closing D6, the one place X-006 recorded this package breaking its
# own rule: the second and later addresses in a message were dropped without a
# word. Five entries: the original silence, counting duplicates as further
# accounts, the threshold moved off ONE, the count replaced by a word (F2's
# shape against the new notice), and the refusal path dropping it while the
# success path keeps it.
#
# 65 to 81 by a THIRD cold pass. Fifteen entries for F1, one per emitted value
# that survived a source-side enumeration, and one for F2.
#
# What earned sixteen entries at once is the METHOD, and it is worth stating
# because two earlier rounds looked harder at the same code and missed this.
# Both of those enumerated from the TEST side: they read the assertions and
# asked which were weak. That cannot find a value with no assertion at all,
# because there is nothing to read. The third pass enumerated from the SOURCE
# side instead, listing every interpolation the package emits into
# ProviderResult.text and demanding each one be able to go red. 46 values, 15
# survivors, and owner_count appeared ZERO times in the entire suite.
#
# The rule: the population to enumerate is what the code EMITS, not what the
# tests already mention. An audit that starts from the tests can only ever grade
# the tests that exist.
#
# 81 to 86 for the tree-integrity precondition. This harness rewrites source in
# place and restores in a `finally`, which a hard kill does not run. An
# interrupted `git commit` proved it: src/core/response.ts was left carrying
# `if (false && ...)` across a live guard.
#
# The five entries all reintroduce a way the precondition could fail OPEN, which
# is the only direction that matters here. A guard that wrongly BLOCKS wastes a
# minute. A guard that wrongly PASSES lets this harness snapshot a poisoned file
# as "the original", restore to it, grade every entry in this file against it,
# and print "all files restored byte-identical" over the top.
#
# 86 to 92 for the WIRING of that precondition, which is a different thing from
# the precondition working. Its first structural test asserted the call exists
# and precedes the snapshot, and `staleSentinelRefusal(ROOT);` alone on a line
# satisfies both while refusing nothing.
#
# Three shapes across both scripts: the result discarded, the test inverted, the
# exit removed. Stated per script rather than swept over both, because a rule
# enforced by one loop over two files is a rule nobody notices losing a file.
#
# This is also where check.ts and checks/mutations.ts became TARGETS, which has
# a second effect worth knowing: TARGETS is what the sentinel records, so the
# two scripts that run the gate are now watched by it too, not just the source
# they grade.
#
# One entry of the six had to be written twice, and the reason generalises. This
# file is the only target that QUOTES its own targets, so a single-line anchor
# like `if (staleTree !== null) {` matched both the code and its own `find:`
# string, and the harness correctly refused it as STALE. The fix is a two-line
# anchor: a real newline cannot survive inside the quotation, where it is stored
# as a backslash and an n.
#
